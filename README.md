# Agent Playbook

Agent Playbook is an open source collection of practical AI and blockchain agents created through the Dunia Hub workshop series.

The project is designed for builders who want to understand how agents use tools, work with real data, coordinate tasks, and prepare actions without depending on expensive services or unnecessary complexity.

## What you will find here

• Ten official workshop agents  
• Beginner friendly examples  
• Reusable agent templates  
• Community contributed agents  
• Setup and testing instructions  
• Free and open model options  
• Safety guidance for tool using agents  

## Official workshop agents

| Workshop | Agent | Purpose |
|---|---|---|
| 01 | Untangle Agent | Turns messy thoughts into a clear action plan |
| 02 | Smart Contract Reader | Explains smart contract code and highlights permissions and risks |
| 03 | Research Agent | Collects sources and produces a structured summary |
| 04 | Booking Agent | Checks availability and prepares calendar bookings |
| 05 | Gas Agent | Reads and explains blockchain fee information |
| 06 | Multilingual WhatsApp Support Agent | Handles customer support across languages |
| 07 | Swap Agent | Prepares a controlled testnet token swap |
| 08 | x402 Pay Per Call Agent | Pays for API access within defined limits |
| 09 | Music Agent | Creates playlists from moods and activities |
| 10 | Multichain Agent Team | Coordinates specialist agents across blockchain ecosystems |

The official agents are located in the `agents` directory.

## Examples

The `examples` directory contains smaller projects that introduce common agent patterns before builders move to the complete workshop agents.

## Community agents

Builders are encouraged to contribute their own agents under the `community-agents` directory.

Start by opening an Agent Proposal issue, then copy the template inside:

`templates/new-agent/`

Read `CONTRIBUTING.md` before beginning a contribution.

## Project principles

• Keep implementations understandable  
• Prefer free and open tools  
• Provide a free path when optional paid services are supported  
• Use testnets by default for blockchain examples  
• Keep people in control of sensitive actions  
• Never commit credentials or private information  
• Document limitations honestly  
• Validate tool results before presenting them as facts
